## ✅ Confirmed Good

Grounded evidence only; each item cross-checked against the merged fact-check and, where the merged report shows a split, against the per-replicate reports (Commit: e5d95a9).

- **The lite-fix dev-eval carve-out fails closed.** `process.env.NODE_ENV === "development" ? " 'unsafe-eval'" : ""` compares strictly against the *permissive* value, so any unset, misspelled, or unexpected environment yields the stricter policy — the opposite polarity from the common `!== "production"` mistake. Appended to `script-src` only; production policy string is byte-identical to the pre-carve-out one. Verified unanimously at k=3 (fact-check Claim 7a) and independently praised by security, architecture, api-consistency, and ui-visual. This is the best-reasoned line in the diff. *(Evidence: `proxy.ts:25-29`; `package.json:6-8` — `next build`/`next start` set `NODE_ENV=production`.)*
- **`.set("x-nonce", …)`, not `.append`.** On proxied paths a client-supplied header is clobbered rather than joined into a comma-list — the failure mode that turns header forwarding into an injection primitive. The instinct is right; Y1 concerns only the paths where the line does not run.
- **The per-request-nonce / static-rendering incompatibility is real, and the waiver's factual premises hold.** Verified unanimously at k=3 (fact-check Claims 2, 3, 11): exactly one page route (`app/page.tsx:1`, `"use client"`), no `generateStaticParams` / `revalidate` / `force-static` / `dynamic =` anywhere under `app/`, and `await headers()` is a genuine dynamic API that opts the route out. The waiver's reasoning is sound given the feature design.
- **The `connect-src 'self'` *rationale* is correct** — all OpenRouter / Lean-verifier traffic genuinely is server-to-server (`callLlm.ts:164`, `streamLlm.ts:249`, `app/api/verification/lean/route.ts:21`, imported only from route handlers and server lib), and all client traffic targets relative `/api/...`. No XHR/WebSocket/EventSource/sendBeacon anywhere. The directive is right; only the in-page `data:` consumer was missed (R2).
- **`base-uri 'self'` and `object-src 'none'` are present and load-bearing** — `base-uri` in particular defeats a `<base>`-tag rewrite of every relative script URL, which would otherwise survive `strict-dynamic`. Both are commonly forgotten.
- **Nonce entropy is sound.** `crypto.randomUUID()` is CSPRNG-backed (122 bits), fresh per request, no `Math.random`, no counter, no per-process reuse. *(Evidence: `proxy.ts:44`.)*
- **Style, font, and image directives are correctly scoped for what this app actually renders.** `next/font/google` self-hosts at build time and `katex.min.css` is bundled with fonts rewritten to `/_next/static/media/`, so every font request is same-origin — the absence of a Google Fonts origin is correct, not an omission. `img-src 'self' data: blob:` correctly anticipates `html-to-image`'s data-URL `Image` step. *(ui-visual Finding 5, Informational.)*
- **No new asymptotics.** No loop, no collection traversal, no cache, no retained state, no allocation sized by user data anywhere in the diff. Every identified cost is a bounded per-request constant; the asymptotic profile is flat.
- **Dependency direction is correct throughout.** `proxy.ts` depends on `next/server` and nothing under `app/**`; no application module was made to depend on the proxy by import. A cross-cutting concern was added without dragging the domain along — the failure mode most CSP retrofits hit.
- **Interface craft.** `buildCsp` matches the repo's `build<Noun>` pattern (`buildUserMessage`, `buildPropositionIndex`) with majority acronym casing; the directive array + `join("; ")` is far more reviewable and diff-friendly than a template literal; `function proxy(request: NextRequest): NextResponse` annotates both sides with a correct type-only import. Path exclusions in the matcher are each explained.
- **The underlying injection surface is already defended.** `react-markdown` v10 renders no raw HTML by default, `rehype-raw` is absent, and no `dangerouslySetInnerHTML` exists under `app/` — so this CSP is genuine defense-in-depth rather than the only thing between LLM output and script execution. That materially lowers the real-world risk of every finding above.
- **No layout regression surface.** The `<html>`/`<body>` tree and the `body` className string are byte-identical; no container, overflow rule, sizing decision, positioned element, padding, or gap is added. No new focusable elements — keyboard-navigation and interactive-state checks are empty by scope, not by omission.
- **Next 16 renamed Middleware → Proxy** (fact-check Claim 15, Verified): `package.json:23` pins `16.2.4`, and Next's own source carries the rename text and deprecation warning.
