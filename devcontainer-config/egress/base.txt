# Source of truth for the Claude Code hosts: code.claude.com/docs/en/network-config.
# Re-check it when a host is added or dropped here. sentry.io and statsig.com were
# removed 2026-09 (security review, finding 7): neither appears in the documented
# requirements any more (statsig.anthropic.com went NXDOMAIN in 2026-07), and each
# was an always-open writable ingestion endpoint. Error intake is switched off with
# DISABLE_ERROR_REPORTING in devcontainer.json instead. Operational telemetry is
# still attempted to a Datadog intake host that is not allowlisted (the firewall
# rejects it); what still gets out rides api.anthropic.com, which is irreducible.
#
# Format: one entry per line, `domain[:port[,port...]]`. Blank lines and #-comments
# ignored. The optional suffix is a comma-separated list of TCP ports; when absent the
# entry is admitted on tcp 443 only. A domain needs two or more labels (a bare
# label such as `com` would become a whole-TLD resolver zone and is rejected). The firewall matches destination address AND
# port (a `hash:net,port` ipset), so name every port a host is legitimately used on —
# e.g. `host.docker.internal:11434`, `some.git.host:22`, `mirror.example:443,8443` —
# and nothing else on that host is reachable. UDP is not expressible; nothing here
# needs it. init-firewall.sh rejects a line that does not parse, so a typo fails the
# rebuild loudly rather than silently changing what is admitted.

# EXACT NAMES ONLY. The SNI proxy admits a 443 name only if it equals an entry
# here (GitHub's zones are the one derived exception), so a SUBDOMAIN of an entry
# resolves through dnsmasq (which is zone-based) and is then REJECTED by the proxy
# with `not in allowlist` in /run/cc-sni-proxy/proxy.log. If a client starts using
# `foo.claude.ai` it must be listed as `foo.claude.ai`; listing `claude.ai` does not
# cover it. This asymmetry is the most likely source of the next quiet outage.
#
