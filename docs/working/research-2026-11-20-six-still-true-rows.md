## Design notes

- **N13: one dominant option (Path A).** Options: (1) deny a `..` spelling whose folded form is covered, security's own recommendation; (2) classify a `..` spelling by its resolved path instead; (3) accept the residual. (1) only narrows (H2): no spelling that was denied or asked becomes a defer. It is not free: a `..` spelling whose folded or lexical form is HARD is denied even when the kernel target is SOFT or ordinary (the N13 reproduction itself, and `~/.claude/hooks/../skills/s/SKILL.md`, which matches `hooks/` before the fold); the deny text tells the caller to spell the path without `..`, which is the whole cost. (2) re-opens the case where the resolved target is SOFT, so the kernel target would get an ask on a string the matcher might still deny, two decisions for one write, and it needs more code. (3) leaves a tainted write ungated whenever the matcher does not fold `..` (the open N3/Q-049 question). No owner choice remains: the tightening costs nothing, so no blocked marker. Not done here: the broader redesign (the hook denies the whole covered tier itself), which the iter3 summary named and which is its own decision.
