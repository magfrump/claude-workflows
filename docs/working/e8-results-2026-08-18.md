## What E8 establishes

1. **Precision held at scale: 0 confirmed false positives and 0 clean false
   Confirmed-Goods across 8 cells / ~140 findings.** The central design claim
   holds. Neither historical FP hotspot recurred.
2. **Both false-attestation traps were caught by the fact-check refusing to
   attest.** N10 (unset `LEAN_VERIFIER_URL`) got a RED with an executed ×2
   refutation; pf-A5 (`Math.max` RangeError) stayed a scoped finding with the
   OpenAlex bound Unverifiable-pending — never certified. These are the exact
   rows the historical pipeline stamped clean; the mandatory-execution rule and
   the scope-line requirement inverted both.
3. **The execution arm broke the pipeline-only classes.** N2 (run the gate),
   csp-C4 (compile the matcher — flipped from Confirmed-Good to red), N11 (enable
   the flag under NODE_ENV=production), D5 (probe the write race), N14 (reproduce
   the cache poisoning), the guardrail bypasses (C2, sec-A1, sanitizer BC6/BC7)
   — all landed by execution inside the review, not by static reasoning.
4. **The endorsement-routing loop works in both directions.** Critics submitted
   categorical runtime claims they couldn't self-certify (hygiene connection
   reuse, fscompat double-hash, corpus write-race); Stage 2.5 executed them —
   socket-count probes, createHash counters, overlapping-writeFile probes —
   turning would-be "What Looks Good" prose into execution-backed verdicts, and
   every Confirmed-Good row now cites an executed or scope-covered backing.
5. **pf-R1 (the type-seam root) — the last pipeline-only moat row — was
   reproduced** by the architecture critic with the executed crash corroboration.

## The three misses (and the one precision blemish)

- **csp-R1** (exportGraph `data:` PNG-export break) — the notable miss, and an
  instructive one: it was *masked by* the scoped Confirmed-Good CG4
  ("connect-src blocks no legitimate client request"), whose scope line carves
  out runtime-constructed `toDataURL()` URLs. The provenance rule made the ✅
  technically-true by narrowing it — but the narrowing is exactly what let the
  real defect slip through the gap. **This is the one place the scope-narrowing
  discipline can hide a defect rather than surface it**, and it is the single
  precision blemish (an over-broad-but-scoped CG, not a clean false attestation).
  Candidate refinement: when a critic scopes a positive to exclude a code path,
  the orchestrator should treat the excluded path as an open question routed to
  a finder, not silently absorbed.
- **N15** (img-src blocks external markdown images) — not surfaced; no critic
  traced the img-src directive against the markdown renderer's external images.
- **N9** (unscoped eslint rules crash on first `.cjs`) — the files-key gap was
  noted but the crash mechanism was not traced to a finding.

Non-diagnostic misses: csp-C1 (dev unsafe-eval), corpus-C3 (build-inlining,
Unverifiable-blocked), pf-A4/A7 (enumeration/panel-sibling tier).

## Caveats

- **Config deltas vs the historical pipeline**: k=2 not k=3; orchestrator on
  fable-5; the reviewed states are the dirty commits (same as E1/E4/E7 ranges),
  not the postfix ground-truth range. Recall is directly comparable to the
  56-row rebased pipeline figures; the cost comparison is order-of-magnitude.
- **Two hygiene notes on the run**: one security-probe evidence file was
  mis-written into the corpus clone and relocated (clone left pristine); one
  architecture critic brushed in-clone `security-review-s2/s3` artifacts during
  its trust-boundary cross-ref but treated them as a no-op (a minor blinding
  brush, no finding drawn from them).
- **Precision asymmetry note still applies**: E8's 0 FPs are measured; the
  historical pipeline's precision is unmeasurable retrospectively. The
  comparison is recall-primary.
